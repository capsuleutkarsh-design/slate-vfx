Setting up a project

A new job starts on Build & Ingest. One screen builds the project folders from a template, brings the client's plates in, and puts every shot on the VFX Dashboard.

Build a new project

  1. Project code and folderType the code, for example KLC: it becomes the top folder and the project's code, exactly as typed. Choose the Projects folder; the grey line below says Builds … with the full path.
  2. TemplateThe folders every project and every shot gets. The preview on the right shows them.
  3. Client drive, then Build projectChoose the delivery. Leave Target reel empty to use the reel folders on the drive. Press Build project (or Enter). Nothing is copied yet: Slate first shows you the plan.

The naming rules

Slate refuses a bad name with the reason. It never changes your project code for you.

NameRule
Project code and shot namesEnglish letters A–Z, digits, _ - and . only. Must start with a letter or digit. No spaces, no /, no ... Up to 64 characters. The same rule is used by Add shots on the dashboard, Build & Ingest and Create shots from a bid, so a name refused in one place cannot arrive another way. Shots you already have are never refused.
On the dashboard's Add projectThe code is stored in capitals and can never be changed later. An archived project's code cannot be used again until that project is deleted for good.
Target reel and template namesAny name Windows accepts: no < > : " | ? *, no space at the start or end, no dot at the end, up to 200 characters.

If a folder with almost the same name already exists (for example My-Show when you type MYSHOW), Slate says so and later asks whether to use it or create a new one.

Bringing footage in

Slate reads the whole drive, shows you exactly what it will do, and copies nothing until you press the button that says how many files.

How Slate reads a client drive

The check before copying

The window is called Check before bringing files into and the project code. Its headline says what will happen, for example "Copy 1,240 files (85 GB) - 42 shots in 3 reels - into …". Read it top to bottom:

  • Files: Copy or Move. Copy - leave the client drive as it is is the default. Use Move - empty the client drive only when the source is a scratch copy you no longer need. Each file is removed from the drive only after its copy is checked.
  • The table lists every shot with its reel, how it was delivered, files, size and notes. Double-click a shot name to change it before anything is copied. Tick Only rows that need a look to see just the problems.
  • Colours. Red: a bad name, or two folders that would become the same shot (rename one). Amber: Slate spelled a non-Latin name out in Latin letters; check it. A highlighted name: Slate tidied it (for example sh 060 (client) became SH_060); change it if you need to.
  • Notes under the table say what else Slate noticed: names it tidied, shots already in the project with exactly these files (not copied again), stitches, documents to be filed, paths over 260 characters.

The buttons say what they will do: Copy 1,240 files, Move 1,240 files, Dry run, or Cancel. When there is nothing new the window says "Nothing new on this drive".

Dry run first on a big or strange driveDry run goes through everything and writes a report without copying or creating anything, and without touching the dashboard. Its report is kept in Slate's own folder, not in the project. Settings → Start Build & Ingest in dry run makes it the default for you.

While it runs

Progress, speed and the time left stay at the bottom of the screen ("Copying 410 of 1,240 files · 220 MB/s · about 6 min left"). An image sequence is one line in the log, not 1,200. Every copy arrives as a .partial file and gets its real name only after it is checked, so a copy that dies half-way never leaves a short plate in the project.

  • Pause, Resume and Stop act between files. Nothing is left half copied.
  • Fast mode (check by size) skips only the slower MD5 comparison; every copy is still checked against the source size. Leave it off for a client delivery.
  • Only one ingest can run on a project at a time.
  • Slate checks free space first. If the disk does not have about the size of the delivery plus 10%, it stops before copying. If it cannot tell, it asks before starting.
  • Closing Slate or signing out asks first, with Stop and close Slate or Keep working.

Afterwards: the result and the report

The box lists shots, files copied, failures, documents filed, and the dashboard: new shots, and new scans on shots already tracked. Its buttons are Open report, Open folder and Close. The last run's result stays on screen.

The delivery report is a page saved in 01_Frm Client\_ingest_reports. It lists the shots received, sequences short of frames, files that failed, sequences not fully brought in, shots already in the project, documents filed and anything ignored on the drive. Send it to the client's VFX editor when frames are missing.

Getting the rest in

  1. Retry N failed filesThe button names how many. It works after Slate is restarted too, and also adds the shots it brought in to the dashboard.
  2. Finish the stopped runAfter a Stop, brings the files the run never reached into the same scan version.
  3. The next deliverySame code, new drive, Update project. Each new delivery of a shot becomes the next scan version.

Running the same drive again copies only what is new. Your answers to the stitch question are remembered for the project, so only new groups are asked about.

The ingest lock

If Slate says Ingest already running, someone else is bringing files into this project. Wait for them. If that ingest is not really running (Slate crashed or was closed), the window offers Clear the lock and continue at once to the person who started it, an admin or a developer, and to anyone else once nobody has touched the lock for 6 hours.

Clear a lock only when you are sureClearing a lock that is in use lets two deliveries mix in one scan version.

What happens on the dashboard

With Add shots to the Dashboard ticked (the default), every new shot appears on the VFX Dashboard with status YTS and a Scan Status such as "v001 received" and the date. Shots already tracked are left as they are; only their scan status and frame range are updated, and their artists get a notification that a new scan arrived. Build & Ingest makes no review proxies: make them in the Timeline Viewer when you need them.

CAP Rename: giving files the right names

Rename many files at once. Slate shows every new name first. Read the preview, then press the button.

Two ways to rename

ModeUse it whenExample
Find and replacePart of every name is wrong.Find shot_v01, Replace with shot_v02
Number as a sequenceFiles need one base name and a running number, in list order.Base name shot_010_v01_, Start frame 1001, Padding 4: shot_010_v01_1001.exr, shot_010_v01_1002.exr…

Rename a batch

  1. Add the files, set the orderAdd files…, Add folder… (not its sub-folders), or drop them on the list. For a sequence: Sort by name (IMG_2 before IMG_10), Sort by date modified, or the up and down arrows (Custom order).
  2. Read every rowStatus says Will rename, Unchanged or Conflict, and why.
  3. Rename filesSlate shows a few examples and asks. All or nothing: if one file cannot be renamed, no file is.

The options

  • Case sensitive is off: Shot also matches shot.
  • Use regex: Find is a regular expression. In Replace with, groups are written \1, \2 (not $1). A pattern that is not valid is explained under Find.
  • Keep extension is on: .exr, .jpg are left alone.
  • Sanitize, To lowercase and Re-pad numbers work on the name before the extension. Sanitize keeps letters in any language and keeps the dot before a frame number: plate.1001.exr stays as it is.
  • Number as a sequence has Base name (required), Start frame (1001 unless changed), Step and Padding (4). The number goes straight after the base name, so type a _ or . at the end of the base name if you want one. If the numbers grow past the padding, Slate offers Use N digits.
  • The filter above the list can show Show changes or Show conflicts only, which helps in a list of 3,000 frames. Each frame file is its own row.

What counts as a conflict

Two files landing on one name. A name with a folder in it (/, \ or ..). Characters Windows refuses (< > : " | ? *), a space at the start or end, a dot at the end, or a name Windows keeps for itself (CON, NUL…). A name over 200 characters, or a full path of 260 characters or more. A file with that name already in the folder. The Status column says Conflict - and the reason. Point at the greyed Rename files button to read every reason at once.

Undo

Undo last rename puts the old names back, even when names were swapped or shifted. It runs in the background with progress and Cancel. You see only your own renames (admins and developers see everyone's), and the newest 50 are kept. Undo refuses, changing nothing, if the files were moved or renamed again since. Every rename and undo is written to the studio audit log.

Close the files firstA file open in Nuke or RV cannot be renamed, and because a rename is all or nothing, the whole batch keeps its old names. The Status column names the file and the reason. Close it and press Rename again. If you close Slate during a rename, Slate waits for it to finish.

Stock Viewer: the studio's library

Footage, elements, textures and references reused across jobs. Find a clip, look at it, copy its path for the artist.

Find something for an artist

  1. Search and narrowEvery word must match the start of a word: fire 4K 24fps. Then a category on the left, Look, or All / Images / Videos.
  2. LookSelect a card. Enter plays, Space opens Quick Look (Esc closes).
  3. Copy pathOr Ctrl+C, or drag the card into another program. Paste the path in the ticket or chat.

"HD" finds HD clips, not UHD ones, because a word must match from its start. Search also reads resolution (4K, 1920, portrait), frame rate (24fps), codec, kind (still, movie, image sequence, camera raw) and folder names. The count says 350 assets, or Showing X of N assets when something narrows the list.

Copying an image sequenceCopy path gives the path of the first frame of a sequence, not a #### pattern. Tell the artist it is a sequence; the facts panel shows its frame range (for example 1001–1024).

Favourites and Studio picks

Favourites are yours alone: the star on a card, the Favourite button in the preview, or Ctrl+D. Studio picks are shared with everyone; leads and supervisors mark them from the right-click menu. Use picks for "the approved smoke elements for this show".

Adding to the library

Adding, deleting, tagging and studio picks need the Ingest stock ability. By default leads, supervisors, Production Head and admins have it; the Production Coordinator and Producer roles do not, so for them the Stock Viewer is read-only. If production owns the library at your studio, ask an admin to tick Ingest stock on your role.

  2. Pause or StopBoth work mid-ingest. One ingest runs at a time.
  3. Read the summaryHow many were added, already there, could not be read, and left out (sound, 3D).

Assigning work

  • The shot's artist: click the Artist cell and pick a name, or Unassigned. Or select several shots, right-click, Assign artist.
  • A department's artist, bid days and target: double-click the shot (or press Enter) to open the shot panel. In Departments, each row has Artist, Status, Bid, Actual and Target. Press Apply.
  • On the Board: switch to Board and drag a person from Assign by dragging onto a card. The numbers beside names are their open shots.

Only people whose role Can be given shots appear in the lists. The person is told in the bell ("You have been assigned to…") when the change is saved. A saved status change rings the bell too, for the department's artist or, for the shot's own status, the shot's artist ("SH010 is now RETAKE.").

In the shot panel you can type a department's artist, but it must be a person in Slate; Slate saves it under their real name. Anything else is refused: "… is not a person in Slate. Pick a name from the list, or leave it blank for nobody."

Saving and conflicts

Every change waits as a pending edit until you press one button. Nothing you type is lost silently, even when two people edit the same shot.

Saving

  • The button at the top right counts your edits: Save 6 changes (1 shot). Ctrl+S does the same. It reads Saved when nothing is waiting.
  • Ctrl+Z takes back the last change, Ctrl+Y puts it back. The Undo on a message takes back only that change.
  • Other people's changes arrive without a refresh. A shot you have pending edits on is never replaced, only marked with ⚠; check it before you save.
  • When the studio database cannot be reached, a red banner says so and the dashboard is read-only until it is back. Nothing you see is lost; press Try again.
Publishing approved shotsWhen a shot is saved as APPROVED, Slate asks Publish approved shots: copy the comp renders to the shot's output folder (08_Deliver on new projects) now? Choose the copy button, or Not now. Files with the same name there are replaced.

The Excel backup

Slate writes a copy of the project to an Excel file in the background after every save. The top bar says Backup saved 19:21, or Backup failing when the file is open in Excel on someone's PC or the share cannot be reached. Manage project → Export to Excel (backup now) writes it at once.

  • The file is in the server's Tracking folder, named after the project code, unless Edit current project… points it somewhere else.
  • It has every column: targets, In/OS, edit status, description, versions and each department's artist, status, bid and actual days, with a frozen header and a filter.
  • Text that starts with =, +, - or @ is stored as plain text, so opening the file can never run anything.
Slate never reads the Excel file backThe backup is a copy for the client and for safety. Typing into the sheet changes nothing in Slate. Make every change on the dashboard. Close the sheet after looking, or the next backup fails.

Projects

History. Right-click a shot and choose View history: every saved change, who made it and when, newest first, with Load older.

Timeline Viewer: the lineup, RV and EDLs

The edit as the dashboard knows it: plates in reel order, each department's render on its own layer. Watch it here or in RV, and hand it to editorial as an EDL.

Check the lineup

  • Every shot with a scan starts ticked. Untick a shot to leave it out of RV and the EDL. Ticks are not saved: Refresh from Dashboard ticks everything again.
  • Frames and FPS come from the plate: a sequence's frames, a movie's own length and rate. Image sequences use the project's Frame rate (sequences). A rate in amber differs from the rest of the lineup; ask the client before you export.
  • length unknown means neither the plate nor the dashboard says how long the shot is. It is drawn hatched in the strip and gets a 100-frame placeholder in the EDL.
  • Where a department keeps versions (Output\v002, or _v002 in the file name), the newest is used. The plate is always the newest scan version.

Render proxies

Heavy EXR frames stutter. A review proxy is a small MP4 that plays smoothly here and in RV.

  1. Tick the shotsProxies are made for every department of the ticked shots that has frames, plate first.
  2. Make review proxiesGreyed out until a shot is ticked. Slate counts what is missing or out of date and asks Make N proxies?
  3. Stop, or read the summaryStop making proxies stops between shots. At the end: "3 proxies made, 1 already there, 2 failed"; failures are under Details.
  • Where they go: into a proxy folder next to the frames. For a plate that is inside its scan version, for example 01_Scan\v001\EXR\proxy.
  • What they are: H.264 MP4, no sound, fitted inside 1920×1080 without cropping or stretching, at the project's frame rate. A missing frame holds the previous one. Movies get no proxy; they play as they are.
  • A proxy older than its render is made again. When everything is current, Slate says "Every proxy for the ticked shots is already there." and offers Rebuild all. Use Rebuild all after changing the project's frame rate.
  • Make proxy under the player makes one for the shot you are watching, when it plays raw EXR, DPX or TIFF frames.
When a proxy failsEach proxy gets a minute plus 2 seconds per frame, so long shots have time; only a proxy that hangs is stopped and counted as failed. Open Details to see which. If the message says ffmpeg was not found, no proxies can be made on this PC: raise an IT Support ticket.

Open in RV

Open in RV plays the ticked shots in RV, in edit order, showing the Layer chosen beside the player. A shot without that render shows its plate. With Use proxies in RV ticked (the default), an up-to-date proxy plays instead of the frames. Each press opens a new RV window.

Inside RV, the Slate menu has Approve Current Shot, Retake Current Shot and Send Note on This Frame.... It needs the VFX Dashboard open on that project, and a role that may edit the dashboard.

  • When Slate can tell which waiting version you were watching (from its folder or its vNNN), the verdict is saved on that version, as in the Review queue: "RV: SH010 v002 set to Approved." The version leaves the Review queue, and the shot's status changes as a pending edit for you to save.
  • Otherwise the verdict goes on the shot as a pending edit: "RV: SH010 marked Approved. Not saved yet - save it in the VFX Dashboard."
  • A note with no verdict is saved on the version ("RV: note saved on SH010 v002.") or, when no version can be told, reported as "RV: SH010 given a note…".
"RV is not installed on this machine, or could not start - tell IT."RV comes with Slate Studio. This message also appears when the shot's media is not where Slate expects it. Check the project share is connected, then raise an IT Support ticket with the shot name.

Export EDL: one per reel, and one of every reel

  1. Choose the Layer, tick the shotsLayer beside the player: Scan for plates, Comp for comps, and so on. Ticked shots hidden by a filter still go in.
  2. Export EDLThe EDL written window says how many shots and reels, and what it left out.
  3. Open folderOr Copy path, and send the files to editorial.

The EDL's frame rate is the most common rate among its shots. Shots at another rate are still written, and the summary counts them. Shots with no scan on disk are left out and listed under "No scan on disk yet, so left out:".

Scheduling: the plan on the calendar

Milestones for every project: turnovers, first passes, reviews, deliveries. Who owns them, what waits on what, and where they sit on the calendar.

Open Scheduling in the sidebar. The same plan has three views. Search, the Project, Status and Owner filters and Show archived projects work in all three.

ViewWhat you see
TableEvery milestone with its project, what it depends on, dates, status, owner and department. Click a heading to sort.
TimelineA Gantt chart: one bar per milestone, grouped by project.
PeopleOne lane per person: the milestones they own, their work from the VFX Dashboard, and their approved leave. Read-only.

Add a milestone

  1. Press Add milestoneChoose the project. Type a name (up to 120 characters, not used before in that project).
  2. Dates, status, ownerStart, End, Status and what it depends on (same project only). Optionally an Owner, a Department and the Effort in artist days.
  3. Add milestoneThe button at the foot of the form. It stays off, and its tooltip says why, until the milestone makes sense.

Picking what it depends on moves Start to the working day after that milestone ends, and says so. The form checks as you type. The end cannot be before the start. Nothing can start before the milestone it waits on has ended. A date on a weekend or a holiday is pointed out, but allowed. Giving the milestone an owner who has approved leave in those dates is allowed too, but the form tells you, so it is your decision and not a surprise.

To change a milestone, double-click it, or select it and press Edit…. Opening a milestone never changes it. Delete… asks first, and the message afterwards has Undo. Milestones that waited on a deleted one are kept; they simply stop depending on it.

Status

Select one or more milestones and press Change status…. The statuses are Scheduled, In Progress, On Hold, Blocked, Completed and Cancelled. Slate records the date a milestone was completed. Marking something Completed while the milestone it waits on is still open asks first. Undo is offered for a few seconds afterwards.

Shift dates: when the client moves a date

Select the milestone and press Shift dates…, or drag its bar on the Timeline (drag an edge to move only the start or only the end). Nothing is saved until you have seen the preview. It lists every milestone that moves with it, the ones that stay and why, and any dependency the move would break.

You chooseWhat it means
Working days or calendar daysWorking days step over the weekly offs and the studio-wide holidays.
How far to push what followsOnly as far as it has to (any slack is kept), or by the same amount.
Completed and cancelled milestonesNormally they stay where they are. You can tick them to move too.

Breaking a dependency needs its own tick. Everything is saved together, all or nothing, and Undo puts the old dates back.

Which days are working daysThe weekly offs come from Studio policy (Sunday only, unless your studio changed it, so Saturday counts as a working day). Shifting never looks at anyone's leave. Only holidays for the whole studio (place "All") are non-working days in Scheduling. A holiday of one office only is not skipped, because projects do not belong to an office yet.

People: who is overbooked, who is away

The People view draws each person's milestones and their dashboard work (artist, department, bid days and target date). Their approved leave is shaded as away. The list beside it names every problem: work planned while somebody is away, and days booked with more than a day of work. Click a problem to jump to that person and day. A dashboard task is drawn ending on its target date, as many working days long as its bid days; tasks without a target date or bid days are only counted. A milestone counts towards overbooking only if it has an Effort. The list only warns.

Only approved leave showsA leave request still pending is not on the plan. Chase the approver; do not plan around a request that may be refused. To change who does what, change the shot on the VFX Dashboard. The People view only reads it.

Who can change the plan: anyone whose role opens Scheduling can see it. Changing it needs Edit the schedule; without it the screen says Read-only and a double-click opens a milestone to read. Every change is kept in the history.

Bidding: pricing the job

What each job is priced at before it is agreed, every revision of that price, and, once it is won, how the real work is tracking against it.

Build a bid

  1. New bid, then add linesChoose the project and the client. Each line: shot and reel (both optional), department, complexity, number of shots, days per shot, day rate, note.
  2. Add shots from tracker…One line per shot already on the dashboard. Omitted and cancelled shots are left out.
  3. Create bidStays off, saying why, until every line has a description, days and a day rate.

Picking a complexity fills in the studio's days per shot for it; you can still change it on the line. The editor totals as you type: artist days, cost, margin, price, discount, subtotal, tax and the total the client pays. Enter moves to the next field. It never saves the bid.

WordMeans
PriceThe amount before the discount.
SubtotalThe amount after the discount. The bid list shows this.
below costThe discount is bigger than the margin. The editor warns, and Save asks first.

Money, currency and tax

A bid is in rupees (INR; the currency list shows the rupee sign) unless the studio changed it, or in the client's currency: US dollars, euros or pounds. Totals in different currencies are never added together. Rupee bids start with GST at the studio rate (18% unless changed); other currencies start with no tax. Both can be changed on the bid. Changing the currency of a draft asks whether to use the studio's day rate in the new currency, so 8,000 rupees a day does not become 8,000 dollars a day. Bids made before currencies were recorded are in US dollars.

Send, win, lose, revise

  • Mark sent records when it went to the client. Won and Lost record the answer, with who and when, and ask first. All three offer Undo.
  • Won and Lost need the Approve bids ability. Nobody decides a bid they made themselves, except Admin and Developer.
  • A sent or decided bid opens read-only. To change it, press New revision: a draft copy (v2, v3…). The earlier revision is kept exactly as it was. Tick All revisions to see old ones.
  • More holds Compare revisions… (lines added, removed and changed, and how the price moved), Duplicate to project…, Export bid as PDF…, Export list… and Create shots on the dashboard….

The cards. Open pipeline counts draft and sent work, but only the newest open bid per project, because several drafts for one job are versions of one price. Won counts every won bid. Archived and superseded bids count in neither.

After the bid is won

  1. Create shots on the dashboard…Under More. Adds the shots the bid names, with each department's bid days. Shots already there are left exactly as they are.
  2. Watch TrackingSelect the won bid. Tracking below the list compares it with the dashboard, department by department.
  3. Export…Saves the tracking figures as numbers, for a spreadsheet.
Tracking columnWhere the number comes from
BidThe days on the bid.
PlannedThe bid days on the dashboard's department tasks.
DeliveredDays of tasks in a done status. Delivered % is the share of the bid delivered.
ActualThe Actual days typed in the dashboard's shot panel. A dash there means "not recorded".

A department planned or spent above its bid is red. Tracking also lists shots that were bid but are not on the dashboard, and dashboard shots the bid never priced. Omitted shots are left out.

Fill in Actual daysTracking can only compare what was recorded. Ask leads to fill in each department's Actual days in the shot panel when a shot is finished. The gap between bid and actual is the best input to the next bid, which is why sent bids are never deleted.

Bidding settings… (under More, for people who approve bids) holds the studio's figures: days per shot by complexity, the default and highest margin, the day rate per currency, the GST rate, and the studio name printed on bid PDFs. The people who approve bids change them, the same as in Settings → Studio currency, rates and hours. Bids already made keep their own figures. A bid PDF leaves out cost and margin, and says it is valid for 30 days.

Who can do what: making and changing bids needs Edit bids; without it the screen says Read-only. Won and Lost need Approve bids (Production Head, Admin, Developer by default). Only an Admin or Developer can delete a draft for good (you type DELETE), and only one never sent, decided or revised.

Who has BiddingProduction Head, Production Coordinator and Producer have the Bidding screen and Edit bids, on new studios and on studios upgraded to 2.2.0. If your studio took Bidding off your role, ask an admin.

The production office in Slate Operations

Your own attendance and leave, the team's leave if you are the Production Head, and project rest after a delivery.

Slate Operations shows the PEOPLE group: Attendance, Leave and, for HR and IT only, Joining & Leaving. Production roles see Attendance, Leave and IT Support like everyone else. Closing Slate or signing out never punches you out.

Production Head: the first leave decision

The Production Head role can approve leave at the first stage, for the people who report to them. Open Leave → Queue. The filter starts on Waiting on me.

  • The Days column is what the request really costs; Slate has already applied holidays and the sandwich rule, and the person saw the same figure before sending. Balance after shows what is left.
  • Your question is only: can the job spare them those days? Check the delivery dates in Scheduling. The Away today card counts approved leave running now.
  • Approve sends the request on to HR for the final decision. Reject needs a reason. Either way the person is told in the bell, with the reason for a rejection, and when you approve, the HR approvers are told a request is waiting.
  • A request already with HR shows HR in Waiting on, and your buttons stay off.

In Attendance, a day covered by a request nobody has decided yet shows as Leave pending (LP in the export); it still counts as absent until it is approved. Production Coordinator and Producer roles do not approve leave. If your team's requests reach nobody, HR decides them.

Project rest after a delivery

Joining & Leaving

The checklist has an HR half and an IT half. No line belongs to production, and production roles do not see the screen. When a freelancer's last day on the show is decided, tell HR: HR starts the leaving checklist, and IT collects every machine the person holds.

Your settings

Settings → Your preferences holds three things worth setting once:

  • Project root: the project folder Build & Ingest opens with.
  • Start Build & Ingest in dry run: Dry run starts ticked, so nothing is copied by mistake.
  • Remember last folders.

Settings has one Save changes for the whole page. Workspace Info (bottom of the sidebar) shows the version, database and shared folder, with Copy details: paste it into every IT Support ticket.
