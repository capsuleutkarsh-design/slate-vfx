Slate Studio Handbook

Three programs, one studio. Find your program below, then follow the pictures. Every step is one thing to do.

Slate Studio

Artists, leads, coordinators, supervisors. Shots, footage, review, dashboard.

Slate Operations

HR, IT, production office. Attendance, leave, joining, hardware, tickets, accounts.

Slate Server

One IT person, one machine. The database everyone else talks to.

How the studio fits together

There is one server computer, one shared folder on the network, and everybody's workstations. Slate on your workstation talks to both.

Every day: signing in

  1. Turn on your PCSlate opens by itself when Windows starts.
  2. Type your Employee IDIt looks like EMP0012. Slate remembers it next time.
  3. Type your passwordDots hide it. That is normal.
  4. Press LOGINYour name shows at the top of the window when you are in.

Attendance: two buttons a day

  1. Morning: PUNCH INOpen Attendance, press the green button. Logging in to Slate also records you.
  2. From home: WFHPress WFH instead of PUNCH IN. Your day is counted as work from home.

Slate Server

One machine, one switch. The server holds the database. When it is off, nobody can sign in.

The four screens

ScreenWhat it is forHow often
DashboardSwitch the database on or off. See IP, port, how many people are connected, which folder holds the data, how many tables.Look every morning
AnalyticsWho is connected right now. Disconnect one stuck session without stopping everyone.When something is slow
OperationsBack up. Restore. Tidy old backups. Vacuum and reindex. Run Diagnostics. Open or trim the log.Back up weekly at least
SettingsDatabase folder, ports, database name, password, firewall button, Check for Updates.Set once

Every week: take a backup

  1. Operations → Back upA file is written. The screen shows "Backed up to ... ".
  2. Copy the file awayIt sits in Slate_Central\Backups beside the database. Copy it to the shared folder or a USB drive.
  3. Check the dateThe Operations screen shows "Last backup N days ago". Red means overdue.
  4. Tidy"Prune" removes backups older than 30 days but always keeps the newest 7.

The dashboard warnings

"exists but has no tables"Normal on a brand-new studio until the first workstation signs in and builds the tables. If the studio is not new, the server is pointed at the wrong folder: Settings → Database Root Path.
"another database on this machine has data"The server is serving an empty database while the real one sits in a folder it names. Point Settings at that folder and restart. Do not create a new one.
"No database password is configured"Set it in Settings and restart. Without it the server cannot create the accounts workstations sign in with.

For IT: installing, moving, updating

Install in this order

First start of the server

  1. Open Slate ServerSettings: check the database password is filled in. Press the Firewall button once.
  2. Flip the switchIt asks "Where is the studio's database?"
  3. New studio: createPress "Create a new empty database here". Existing studio: press "Use an existing database folder" and pick it.
  4. Sign in from one workstation as adminThat builds the tables. The dashboard table count goes above zero.

Where things live

WhatWhereSafe to delete?

Temporary unpacked copy of the server%TEMP%\_MEI...Yes, when the server is stopped

Moving the server to another machine

  1. On the old machine: Back upOperations → Back up. Copy the .dump file to a USB drive. Or, with the server stopped, copy the whole LocalDatabase folder.
  2. UninstallWhen asked "Delete its settings and data as well?" press No until the new machine works.
  3. On the new machine: install and startChoose "Use an existing database folder" and point at the copied folder. Or create new, then Operations → Restore with the dump.
  4. Point the workstationsGive the new machine the old one's IP, or on each workstation use Reconfigure Server / DB and type the new IP.
Never run two servers on the same dataTwo machines serving two copies means two sets of edits nobody can merge. Old off, then new on.

Updates without internet

Build the update package on the developer PC with the Launch Console, "Build update package". It writes the package and a manifest into Slate_Central\Updates\releases. Every workstation checks that folder when it starts and offers the update; the server offers it from Settings → Check for Updates. Nothing else is needed.

Uninstalling

The uninstaller removes the program and then asks one question: delete the settings and data too? No keeps everything, and a reinstall picks it straight back up. Yes on the server deletes the database and every backup on that machine. Answer Yes only when you mean to start over.
